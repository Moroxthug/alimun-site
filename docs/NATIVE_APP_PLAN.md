# The Alimun app, built natively

Owner, 16 Nov 2026, after trying the Android builds made from the website's screens (`mobile/`, Capacitor): "this version sucks mate. Which serious platform uses browser app? Please, create a multi step plan for the app and let's get started creating a full and complete app and stop with this browser bs." On the phone the pickers for the language and the time were broken, the app still showed class prices, and it felt like the website.

Decision: the learners' app is rebuilt as a real app. It replaces the plan of `docs/APP_PLAN.md` ("one codebase: the dashboard at /app becomes the app"). The website's `/app` stays for browsers. `mobile/` (the web shell) is kept only until the new app covers it, then removed; `mobile/admin/` (Alimun Admin, owner only) stays as it is.

## How it is built
- Flutter (Dart), in `native/`. One codebase compiled to a real Android app and, later, a real iPhone app: its own screens, lists, pickers, animations and gestures, drawn by the app at the phone's refresh rate, with no web page inside. Package `com.alimun.app`.
- Why Flutter and not Kotlin for Android plus Swift for iPhone: one set of screens for both phones instead of two; the animation and custom-drawing tools the design needs; ready parts for everything Alimun uses (Supabase, Daily live classes, audio in the background, local notifications, home-screen widgets, Google Play and App Store purchases through RevenueCat).
- The server does not change: the same Supabase database and row rules, the same `/api` functions, the same course files (`/data`, `/api/material`) and recordings. The app signs in with the same accounts.
- Design: `CLAUDE.md` and `docs/DASHBOARD_PLAN.md` apply unchanged (palette, Coolvetica Condensed and Satoshi, the drawing cast, the owner's loader, no black backgrounds, no chips, no numbered steps, no emojis). The drawings are the same SVG files, exported from `js/app/cast.js` and `cast3.js` by a script.
- Text: only in `js/translations.js`. A script writes the keys the app uses into `native/assets/i18n/<lang>.json` for the nine languages. The language is chosen in the app's settings and applied at once.
- Everything the learner has opened or downloaded is stored on the phone (a local database and files), so the app opens and works without a connection; what is done offline is sent when the connection is back.
- Checking: screens are rendered to pictures in the build machine (Flutter's own test renderer) and the logic has unit tests; the APK is built here. Nothing can be run on a phone from here: the owner's phone is the test after each step.

## Steps
Each step ends with an installable APK for the owner and is confirmed before the next.

1. Foundation. The project, the design system (colours, type, buttons, cards, fields, sheets, the loader, the drawings), movement between screens, the nine languages with the language setting, sign in, create an account, forgot password, the first set-up, the shell with the bottom bar and More, Home with the learner's real data, Settings (profile, language, password, sign out).
2. The course book. Units, lessons and pages turned by swipe, every block (text, examples, tables, dialogues, tips, readings), the explanation-language switch, the exercise engine with the 19 kinds and the character reactions, unit tests, progress saved, the free limit, downloads for offline, recordings.
3. Practice and flashcards. Practice rounds, quizzes, beat the clock, long sets, sets from the teacher; flashcard decks, spaced review, own cards.
4. Library and mock tests. Listening with the line being spoken marked, slower playback, playing with the screen locked and lock-screen controls; readings with tappable words; mock tests with timer, parts, marking and results.
5. Classes. The timetable and calendar, joining a live class (Daily's own phone SDK: video, chat, board), class notes and words, finding and joining a class, 1 on 1 bookings, homework (writing, speaking, hand-in, feedback), messages, progress, notifications.
6. The tutor. The written tutor with its board, past sessions and memory; the voice tutor and pronunciation checks; tutor time.
7. Only in the app. Review and class reminders, saving a word from any app through Share, the home-screen widget, shortcuts on the icon, the bottom bar the learner arranges, with animated icons.
8. The store version. The release key, version numbers, the signed bundle, Google Play purchases for the app plan and tutor minutes through RevenueCat (classes and packs: no prices, buttons or links in the app, owner 14 Nov), account deletion in the app, the listing, screenshots, data safety, the AI notices. Then iPhone from the same code (needs a Mac build machine and an Apple developer account).

The app opens `app/check.html` out of sight in a small web view (`lib/captcha.dart`), takes the token and closes it; if Cloudflare asks for a tick it shows in an Alimun card. This is the only web view in the app.
- New texts: `app_st_applang_h`, `app_st_applang_p` (nine languages). Names of the six course languages are a table in `lib/i18n.dart` (the website gets them from the browser).
- Not in this step: prices and buying (step 8), the level test in the app, account deletion in the app, notifications.
- Checked: `flutter analyze` clean; nine screens rendered to pictures at phone size (`native/test/screens_test.dart`, `native/test/shots/`), right-to-left layout included; the release APK builds. Not checked: anything on a phone, and a real sign-in (the person check needs the phone and the live page).

### Step 2: the course book (built 17 Nov 2026, waiting for the owner's check)
- The Book section is native (`lib/screens/book.dart`): cover (continue card, buddy, draft note, goal books, units with progress, locked units "Comes with a plan" with no price or link, units being written), unit (lessons, unit test card), lesson (pages turned by swipe or the buttons, the page lifting over its spine: `lib/book/turner.dart`; progress bar; the next page opens when the page's exercises are done; celebration page), unit test (nothing marked until "Check my test", 70% passes, result with the score counting up, take it again).
- Blocks (`lib/book/blocks.dart`): text with bold and italic, examples whose note opens on tap, tables (three columns or fewer wrap; wider ones are shrunk to the page and open full screen with pinch and + / − zoom; "Test yourself" hides the cells until tapped), dialogues arriving line by line like a chat, tips with a drawing and bubble, readings. Explanations follow the switch (my language or the language being learned); text in the language being learned is always left to right.
- The exercise engine (`lib/book/engine.dart`, `lib/book/marking.dart`, drawn by `lib/book/exercise_view.dart`): choice, gap, order, match, tf, spot, odd, select, wordform, transform, conjugate, crossword, build, colloc, fix, bank, sort, memory, search, and also picture, label and speak (the books use them). Lesson mode with the book character's reaction, a light buzz on right and a heavy one on wrong, the explanation, "Show the answer" after two wrong tries; test mode. Words are tapped, not dragged (new hint texts without "you can also drag").
- Same marking as the website: `node native/tool/marking-cases.js` runs `js/app/exercises.js` without a browser on exercises from the books and writes `native/test/fixtures/marking.json`; `native/test/marking_test.dart` replays it through the app's engine (14,000 typed answers, 55 crosswords, 31 word searches, 1,400 exercises played in lessons and tests, 21 kinds; speak is checked on ten sentences). Run both after changing either engine.
- Data (`lib/book/store.dart`): books from `/data/books/<book>.<lang>.json` (free) or `/api/material` (plan; a 403 removes the complete files from the phone), kept as files in the app's own folder and opened from there at once, refreshed for next time; progress in `practice_progress` and the practice memory in `practice_items` as `js/app/data.js` writes them; writes that cannot be sent wait in `outbox.json` and go out when the app starts, comes back to the front, or 40 seconds later; progress is also kept per book for offline opening.
- Recordings (`lib/book/audio.dart`, just_audio): play buttons on examples, Listen and Slower on dialogues and readings where files exist, the line or paragraph being spoken marked. "Download for offline" on the cover fetches the book in both explanation languages and every recording into the app's folder, with progress, size and Remove.
- Speaking (`lib/book/speak.dart`, record): records up to 15 seconds, sends it to `/api/ai?action=transcribe` as the website does, marks the words heard. Needs the microphone permission (new in the manifest).
- New texts (nine languages): `app_book_order_hint_tap`, `app_ex_bank_hint_tap`, `app_ex_sort_hint_tap`, `app_ex_label_hint_tap`, `app_ex_speak_mic_app`. New drawings exported: the book character's moods, picture objects, scenes, tutors.
- Checked: `flutter analyze` clean; 44 tests pass (marking, step 1 pictures, the Book pictures in `native/test/shots/book-*.png`, Arabic explanations included); the release APK builds (22 MB). Not checked, because it needs a phone: how the page turn and the haptics feel, sound playing, the download with real files, recording and the microphone prompt, typing with the phone's keyboard, the real sign-in, loading a book over the network and saving to the database from the app.
- Not in this step: dragging tiles; lip movement of the tutor; listening kinds (hear, heargap, dictation: Practice, step 3).

## Setting up the build machine (each new cloud session starts without the tools)
Java 21 is installed; Flutter and the Android SDK are not, and the scratchpad of an earlier session is gone. In the session's scratchpad `S`:
- Android: download `https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip`, unzip to `S/sdk/cmdline-tools/latest`, then `yes | sdkmanager --sdk_root=S/sdk "platform-tools" "platforms;android-36" "build-tools;36.0.0"` (the first build also fetches the NDK and CMake by itself, about six minutes).
- Flutter: the stable Linux archive named in `https://storage.googleapis.com/flutter_infra_release/releases/releases_linux.json` (3.50.0 on 16 Nov 2026), untarred to `S/flutter`; `git config --global --add safe.directory S/flutter`; `flutter config --no-analytics --android-sdk S/sdk`; `yes | flutter doctor --android-licenses`.
- In `native/`: `echo "sdk.dir=S/sdk" >> android/local.properties` (ignored by git), `flutter pub get`, `node tool/export.js` from the repository root, `flutter analyze`, `timeout 900 flutter test --update-goldens` (marking tests and the pictures of `test/screens_test.dart` and `test/book_shots_test.dart` in `test/shots/`; pump in small steps, entrance animations need several frames; real file or network work inside a test goes through `tester.runAsync`), `flutter build apk --release --target-platform android-arm64` (22 MB, debug-signed until step 8). Maven Central sometimes answers 429 on the first build: wait a minute and build again. The website's `npm run build` needs `npm ci` first.
- This Flutter version keeps Material in the package `material_ui` and Cupertino in `cupertino_ui` (import `package:material_ui/material_ui.dart`, not `package:flutter/material.dart`); follow `flutter analyze` over memory.
